## Context

用户已确认 React + Ant Design + ProComponents，独立管理网页先迁移现有四项能力。开发原型位于 `docs/shopee_admin_prototypes/`，全部为模拟值，仅作视觉参考。当前不存在已归档的 OpenSpec 规范。

现有入口为 `components/product/AdminPanel.tsx`，依赖 popup 的 API、类型和扩展认证存储；后端管理接口已存在于 `backend/src/routes/admin.ts`。`authMiddleware` 验证 JWT，`adminMiddleware` 却只检查 token 的 role，已撤权账号仍可能被放行。绑定列表返回 SPC_CDS，网页不应传输它。删除用户使用 `payload.id` 而 token 身份为 `userId`，需修正现有自删保护。

## Goals / Non-Goals

**Goals:**
- 管理员无需扩展即可登录网页，使用现有用户、绑定、邀请码、统计功能。
- 独立构建、默认中文、真实数据、必要安全修正、用户确认后移除旧面板。

**Non-Goals:**
- AI、选品、上架、通用任务引擎、计费、补历史记录、数据采集改造、趋势分析、导出、数据库迁移。
- 生产部署、域名配置、真实店铺操作、旧文档清理及整体后端重构。

## Decisions

### 1. 独立前端，同一后端

新增 `admin-web/`，独立 package、锁文件、构建目录，采用 React + TypeScript + Vite + Ant Design + ProComponents。安装前核对稳定版本、React 兼容关系与许可证，记录实际采用版本，不因选型顺带升级扩展依赖。不采用整套 Ant Design Pro，不叠加 Tailwind/shadcn 或图表库；本轮以菜单、表格、表单和数字文本展示完成迁移。

本地 Vite 将 `/api` 代理至本地后端；正式本地验收由现有 Hono 托管构建产物 `/admin/`，网页请求同源 `/api/`。Vite base 使用 `/admin/`，首版菜单可由页面状态切换，避免额外路由框架与深链回退复杂性。页面托管仅覆盖 `/admin` 路径，不影响 API/健康检查；构建缺失必须明确报错，不能返回模拟页面。网页托管使用确定的构建目录，不接受客户端文件路径。

### 2. 复用账号，隔离登录状态

使用既有 `/api/auth/login` 登录、`/api/auth/check-admin` 核对身份。网页不提供注册，不新建管理员体系；管理员凭据不写入任务、日志或 Git。网页 token 仅放内存，刷新后重新登录，首版不做持久登录；退出清除状态。该方案不新增 Cookie 认证与 CSRF 契约，也不把 token 放网页持久存储。扩展认证方式不变。

所有 `/api/admin/*` 请求由服务端按 token 的 userId 查询数据库，确认账号存在、已激活且当前 role 为 admin；页面检查只是提示，不代替服务端鉴权。修正删除用户自删保护使用 userId。安全修正限定于管理能力，不扩大到其他业务重写。

### 3. 迁移现有能力，不照抄原型业务

- 用户：列表、管理员/激活/绑定数/自动权限/试用状态展示，调整店铺限额、切换自动权限、重置或标记试用、开启或关闭试用限制、删除。
- 绑定：默认展示有效绑定，使用既有 userId 查询可查看指定用户含已解绑记录，保留确认解绑。
- 邀请码：列表、使用状态/用户/时间、每次生成 1–20 个、删除未使用码。
- 统计：现有用户总数、有效绑定数、按事件类型计数。既有事件明细接口可接入本页，保留类型过滤与最多 100 条的真实限制，不承诺完整历史或服务端分页。

普通表格可以对当前已加载列表搜索/分页，必须避免把局部数据过滤描述为全库查询。不新添账号封禁、管理员授权、趋势图或其他原型动作。

### 4. 数据脱敏与操作反馈

管理绑定响应只包含展示和操作所需字段，删除 SPC_CDS 输出；无 shopId 时显示“店铺信息待补全”，不显示凭据前缀。事件详情只展示已确认的非敏感字段，不直接渲染任意 eventData HTML 或泄露 token/Cookie。未知数据标为未知，失败不得展示假成功或零值冒充真实统计。

删除用户明确说明同时删除绑定、事件和验证码；解绑、删除邀请码保留二次确认。提交中禁用重复点击，成功刷新相关列表/统计，失败保留可理解错误。试用限制关闭意味着不再限制手动试用，不将其误标成禁用手动功能。

### 5. 单一管理入口，分阶段移除

用户选择新网站确认可用后移除旧面板。开发阶段保留旧面板供迁移核对，完成本地网页和扩展回归后由规划方安排用户体验；确认前不得提前删除。确认后删除 AdminPanel 与 popup 的管理页面状态/导入/专属请求，保留卖家账号、绑定、权限查询与统计上报。顶部管理按钮改为打开已配置后端的 `/admin/`，不得自动回落生产；无配置则明确提示。浏览器打开新标签页即可，不新增不必要权限。

## Risks / Trade-offs

- 管理站新增依赖 → 独立构建；检查扩展包无 Ant Design/ProComponents 引入。
- 开发环境仍可能误连生产 → 网页固定本地代理，验收独立测试 DB，禁止读取生产 DB/真实凭据，后端启动前确认不会因占用端口杀掉他人服务。
- 当前记录并非全功能覆盖 → 仅呈现已有记录，不宣称完整使用历史。
- 老面板依赖 SPC_CDS → 移除凭据输出时同步调整旧面板缺失 shopId 的展示，维持过渡期可用。
- API 返回绑定限额信息不足 → 如需展示当前限额，仅增加 users 列表 maxStores 字段，保持既有响应兼容，不改限额规则。
- 内存登录刷新即退出 → 首版明确说明，后续若需要保持登录再另行设计。

## Migration Plan

1. 完成独立登录和用户只读列表，核对开发环境。
2. 逐项迁移四项能力，使用小型隔离数据验证写操作和权限拒绝，不访问真实店铺。
3. 构建并由本地 Hono 托管网页，规划方提供用户手测入口。确认后才移除旧面板。
4. 再检查扩展登录、绑定与原有卖家入口；生产发布另行授权。

无数据库结构迁移；回退时恢复上一版管理页面/入口和构建产物，不能回退为依赖旧 token 权限的危险鉴权。操作产生的数据变更并不会随代码回退自动撤销，因此验收仅使用隔离数据。

## Open Questions

无阻挡本地开发的用户决策。生产域名、HTTPS 和部署方式在发布前另行确认；登录持久化、未来功能及原型完整复刻均不默认纳入。
