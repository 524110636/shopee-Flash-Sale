## Context

本轮对象是 Chrome 扩展 popup，不是管理员网站。用户认可功能卡片首页、单张限时特卖卡片、内部手动/自动模式页签和运行任务直达，并提出未来十几个工具及运营/AI 分类的需要。

已核实当前 `App.tsx` 将公共顶栏、认证、绑定、手动操作、向导与自动模式翻转布局放在一起；根容器宽 500px、最小高 500px。`store.ts` 中 `autoModeActive` 表示展示自动页，`autoModeStatus` 表示任务状态；`loadAutoModeStatus` 读到任意保存状态就设置 `autoModeActive: true`，不能将它当作“任务正在运行”。`enterAutoMode` 含权限提示，`exitAutoMode` 只切视图。开卖循环在 background，但一键修复向导部分过程仍由 popup store 执行。本轮不得顺带迁移执行架构。

## Goals / Non-Goals

**Goals:**
- 打开扩展先看到功能首页，进入限时特卖后可切两种模式并返回。
- 导航不清空参数、向导、选品、模板或任务，不产生店铺写请求。
- 公共账号、店铺提示、帮助与已有管理员外链可达；当前权限和绑定校验保持有效。
- 卡片读真实状态，运行/待执行任务能直达对应模式。
- 小型静态功能定义预留分类字段，未来新增工具不必复制公共外壳。

**Non-Goals:**
- 不新增 AI 或其他业务工具，不展示虚构功能、分类菜单、搜索、收藏、拖拽、复杂任务中心。
- 不重写限时特卖操作流程，不变更后台执行、授权、试用扣除、商品过滤和后端接口。
- 不更名扩展产品、不修改权限或引入路由框架，不升级依赖。
- 不发布生产，不用真实店铺做自动测试。

## Decisions

### 1. 功能首页与工作页两层，模式是功能内部页签

首页只展示「限时特卖」卡片。页面顶部有「全部功能」，下方是「手动模式 / 自动模式」，页签取代旋转翻面。两种模式共享业务上下文，不拆成两个独立工具。保留当前 teal 主题与已有组件，不移植管理员网站 Ant Design。

普通卡片入口固定进入手动模式；自动运行状态旁的「查看任务」直达自动模式。手动任务和定时复制/加入的查看入口进入手动工作页。多个已有任务状态可同时展示简短摘要及各自入口，不用单一优先级遮蔽另一个任务。已结束的旧自动记录不显示“运行中”。

替代方案：两张模式卡片会混淆业务边界；每次恢复上次页面会破坏默认首页；增加左侧菜单会挤占 500px 弹窗，均不采用。

### 2. 导航状态独立，任务加载不强制切页

外壳持有首页/限时特卖的轻量展示状态，不持久化跨弹窗页面选择。复用现有 `autoModeActive` 或等价的单一模式展示状态，避免双份模式真源。调整状态初始化时只恢复任务数据，不因保存的自动任务记录切换页面。状态同步和后台监听挂在常驻根层，不能切到首页后停止监听。

进入自动配置继续走现有 `enterAutoMode` 权限检查，不直接赋值绕过权限。如恢复任务存在但权限被撤销，应保持状态可见，并显示现有权限提示，不能因导航重新启动任务。所有执行前的现有服务端校验继续保留。

### 3. 同一 popup 内的页面切换保留工作状态

首选将现有限时特卖工作区域在首次进入后保持挂载，首页只控制可见性；手动/自动区也保持必要状态。隐藏区域不得占布局、接收键盘焦点或拦截点击；弹层须受所属页面可见性约束，不能残留在首页上方。这样无需把向导时间输入、选中时段、编辑草稿等局部状态逐一迁移到全局。

如组件拆分更合适，可将必要局部状态提升至常驻层，但不能通过重建组件丢失数据。返回首页、切模式禁止调用 `reset`、`clearCache`、停止、取消或执行业务动作。

本轮只保证同一个 popup 生命周期内的导航状态保留，以及已有 background 任务关弹窗后的恢复；不承诺仍由 popup 执行的修复向导在关闭弹窗后继续运行。不要为本轮导航改造扩成后台迁移。

### 4. 公共区域与业务校验分层

复用认证与绑定组件，先登录再进入首页。现有绑定信息加载过程仍可有加载态；加载失败或未绑定时，保留重试/绑定入口及明确状态，不能显示“可执行”。首页入口允许查看工具，但工作页内的绑定/身份门控仍拦截业务操作。首页不发起活动/商品列表加载，只保留必要的认证、店铺识别、已有状态恢复。

管理员外链仍走当前配置的后端地址，打不开的提示在公共区域显示，无生产回落。帮助、账号设置与已有定制开发入口可整理位置，不删除能力。原有“自动页隐藏公共按钮”的展示条件需按新公共布局调整，不改变权限规则。

### 5. 尺寸与分类扩展采用最小实现

宽度继续 500px，可视目标高度约 600px，实际高度以 Chrome 和屏幕可用空间为上限。这是布局目标而非保证可增加 200px；用单一内容滚动区，避免双层滚动，公共导航保持可达。两列卡片、统一间距、可见 focus、键盘 Enter/Space 可进入。仅一张卡片时保留自然留白，不拉伸成整屏。

功能定义至少包含 `id`、`categoryId`、`title`、`description`、`icon`、入口标识；限时特卖归属 `shop-operations`。字段名可按已有命名约定调整，必须保持语义。将来 AI 可用独立分类 id，但当前不注册虚构工具、不增加插件加载器、后端分类接口或泛化框架。测试用十几个虚构卡片只能在隔离夹具中，不能混入生产首页。

## Risks / Trade-offs

- [首页多一次点击] → 卡片任务入口直达工作页；普通入口仍保持明确选择。
- [自动模式状态恢复夺走首页] → 初始化仅恢复任务数据，针对有历史状态/运行状态分别测试。
- [卸载丢失草稿或中断监听] → 常驻状态层、首次进入后保持必要组件挂载，测试返回再进入。
- [隐藏弹层或表单仍可交互] → 页面隐藏时同时处理弹层与焦点；禁用隐藏区的可访问性和交互。
- [把权限页签改成直接赋值] → 配置入口复用现有权限动作，不修改校验与扣除时机。
- [首页误触发真实业务] → 浏览器检查导航网络请求，所有卡片和页签只切展示。
- [Chrome 高度不满足期待] → 约 600px 目标、内部滚动；真实扩展加载验证，不将普通网页尺寸当扩展证明。

## Migration Plan

开发先接通首页到现有工作页，再替换模式导航、接入任务状态，完成小范围回归后交规划方验收。先使用开发版与本地隔离后端；真实虾皮请求写操作须阻断，不能认为本地后端隔离了店铺。规划验收后邀请用户只做导航体验，未获体验确认保留待用户确认状态。生产构建仅验证，不自行安装到日常版本或部署。回退仅还原本变更自己的文件，不覆盖已有归档和其他会话改动。

## Open Questions

无阻挡开发的产品问题。具体公共按钮排列、实际可视高度与状态文案由开发按上述约束完成基本版，规划方与用户在本地体验确认；不能借此扩大范围。
