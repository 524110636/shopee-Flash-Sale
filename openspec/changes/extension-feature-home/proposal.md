## Why

扩展目前打开就进入占满弹窗的限时特卖界面，不适合后续承载十几个工具。新增统一功能首页，让用户先选择工具，再在工具内部完成操作，同时保留现有限时特卖流程与任务执行边界。

## What Changes

- 已登录用户打开扩展默认进入功能卡片首页；未登录仍走现有登录流程。
- 首页只显示一张真实可用的「限时特卖」卡片，不拆分手动与自动、不展示虚构的未来工具。
- 功能页提供「全部功能」返回入口与「手动模式 / 自动模式」页签，替代模式翻转动画。
- 卡片展示已有任务状态；自动任务运行时可直接查看自动模式，手动或定时任务可直达对应工作页。导航不启动、停止或重置任务。
- 复用账号、店铺绑定、权限检查、后台任务和现有组件；公共状态与功能业务区域分层。
- 保持 500px 弹窗宽度，目标可视高度约 600px，实际受浏览器和屏幕限制；内容内部滚动，顶部导航保持可达。
- 功能定义预留稳定 id、所属分类、名称、描述、图标及入口；本轮不展示分类菜单、不实现搜索、AI 或其他工具。
- 本轮为本地开发和验收，不部署生产、不提交推送、不操作真实店铺。

## Capabilities

### New Capabilities

- `extension-feature-navigation`: 扩展卡片首页、功能内模式导航、任务状态直达与导航状态保留。

### Modified Capabilities

无。现有 `standalone-admin` 正式规范及管理员网站行为不变。

## Impact

主要影响 `entrypoints/popup/App.tsx`、popup 布局样式、必要的功能首页/导航组件、自动模式展示与相关导航测试。`store.ts` 只允许必要的展示状态与初始化适配：必须解除已存自动状态对首屏强制跳转的影响，不能修改任务执行与权限逻辑。复用现有 WXT、React、Tailwind、shadcn/ui、Zustand，不引入路由框架、后端 API 或新依赖。开发方按实际符号变动更新相关手册；管理员网站、后端、background/content 执行业务不在修改范围。
