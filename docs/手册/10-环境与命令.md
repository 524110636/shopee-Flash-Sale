# 10 环境与命令

> **用途**：起服务、跑命令、连后端、排环境问题。**运维命令的唯一天权威正文。**
> **何时读**：需要重启后端、排查端口、构建扩展、切换开发/生产、连本地后端。
> **来源**：原 `运维速查.md` 全文 ＋ `AGENTS.md` 的 Development Commands ＋ `CLAUDE.md` 的环境与命令表。

## PM2 进程管理

> ⚠️ **启动命令在服务器上的 `backend/` 目录里执行**，不是仓库根目录 —— 入口文件是 `backend/src/index.ts`，仓库根没有 `src/index.ts`。

查看状态
```bash
npx pm2 status
```

查看日志（最近 20 行）
```bash
npx pm2 logs limited-time-sale --lines 20
```

重启
```bash
npx pm2 restart limited-time-sale
```

停止
```bash
npx pm2 stop limited-time-sale
```

启动（首次或停止后）
```bash
cd backend && npx pm2 start src/index.ts --name limited-time-sale --interpreter tsx
```

删除进程
```bash
npx pm2 delete limited-time-sale
```

`limited-time-sale` 是服务器上的 PM2 进程名。

## 构建扩展

本地开发机执行

```bash
npm run build
```

产物在 `.output/chrome-mv3`。

### 构建到自己的隔离目录（做隔离验证时）

**不要**改 `wxt.config.ts` 的 `outDir` 来隔离 —— 那会覆盖用户日常使用的 `.output/chrome-mv3`。做法是用
`-c` 指定一份临时配置，里面只覆盖 `outDir` 与后端地址：

```bash
npx wxt build -c .agent-tmp/<任务标识>/wxt.iso.config.ts
```

那份配置从 `wxt.config.ts` 继承，只改输出目录与 `VITE_BACKEND_URL`／`VITE_BACKEND_FALLBACK_URL`。
**兜底地址必须留空**（红线：否则本地后端一停就静默回落生产库）。构建后核对：

```bash
# 隔离包：应含隔离端口，不含生产 IP
# 生产包：应含 43.99.86.228，不含隔离端口
```

## 日常使用与开发调试

> **这条极其重要。** `npm run build` 与 `npm run dev` 产出的是**两个不同的扩展**，行为完全不同。认错就会遇到「弹窗空白 / 打不开」。

### 日常使用（平时就用这个）

1. `npm run build`
2. 打开 `chrome://extensions`
3. 找到「**限时特卖助手**」（**不带**"开发版"字样）→ 点「重新加载」
4. 加载目录：`.output/chrome-mv3`
5. **不依赖任何本地服务**，关掉终端也照样能用

### 开发调试（改代码时用）

1. `npm run dev`
2. 产出到**另一个目录**：`.output/chrome-mv3-dev`
3. `chrome://extensions` 里会出现名为「**限时特卖助手（开发版）**」的条目
4. **必须保持 `npm run dev` 那个终端开着** —— 关掉后该扩展的弹窗**立即白屏**
5. 本项目已设 `web-ext.config.ts` 的 `disabled: true`，所以 dev **不会自动打开浏览器**；需要自己在 `chrome://extensions` 手动加载 `.output/chrome-mv3-dev`

### 出故障自查：扩展弹窗空白 / 打不开

1. 先看 `chrome://extensions` 里它是**哪一个**：
   - 「限时特卖助手」→ 生产版，不该白屏
   - 「限时特卖助手（开发版）」→ 继续第 2 步
2. 是开发版 → 检查 `npm run dev` 是否还在跑（终端是否还开着）
3. 终端已关 / 没跑 → 要么重新 `npm run dev`，要么**改用生产版**（上面的「日常使用」）

**原理**：dev 版的 `popup.html` 里有三行指向 `http://localhost:3000/`（Vite 开发服务器），其中一行就是 React 入口 `entrypoints/popup/main.tsx`。服务器一停，这三个模块全部 `ERR_CONNECTION_REFUSED` → React 从未挂载 → 弹窗空白。生产版把这些都打包进扩展本身，零依赖。

**快速判断当前是哪个版本**：
```bash
# 含 localhost:3000 → 是 dev 版；无输出 → 是生产版
grep -c "localhost:3000" .output/chrome-mv3/popup.html
```

### ⚠️ 版本切换挡不住店铺写操作

**必须知道**：上述 dev／prod 区分**只隔离扩展的后端连接**（账号、试用、统计），**挡不住**虾皮店铺写操作。

店铺操作由扩展直接打 `seller.shopee.tw`，用的是浏览器里的登录 Cookie，与扩展连哪个后端无关。已实测：`store.ts` 的 `update_product_info`／折扣接口、`background.ts` 的 `set_shop_flash_sale_items` 全部直连虾皮。

**要真正隔离，得另开一个 Chrome 用户配置登录测试小号。**

## 开发期连本地后端

> **为什么要有这一节**：后端地址是**构建时**烤进产物的，不是运行时读的。处理不当会出现两种事故：
> ① 改错文件 → **生产包也指向 localhost**，用户日常用的插件连不上后端；
> ② 兜底地址没改 → 本地后端一停就**静默回落到生产库**，调试动作照样写进生产数据。

### 地址是怎么定的

用按模式分离的两个 env 文件（WXT / Vite 原生支持，**不改任何源码**）：

| 文件 | 内容 | 何时生效 |
| --- | --- | --- |
| `.env.development` | `VITE_BACKEND_URL=http://localhost:5724`；`VITE_BACKEND_FALLBACK_URL=`（**留空**，禁掉回落生产） | 只有 `npm run dev` |
| `.env.production` | 两个键都填生产地址 | 只有 `npm run build` / `npm run zip` |
| `.env` | 现状（生产地址） | 兜底，被上面两个覆盖 |

加载优先级（低 → 高）：`.env` < `.env.local` < `.env.[mode]` < `.env.[mode].local`。

`wxt`（`npm run dev`）= mode `development`；`wxt build` / `wxt zip` = mode `production`。

### 开发期怎么用

```bash
# 1) 先起本地后端（另开一个终端，保持不关）
cd backend && npm run dev          # 监听 5724

# 2) 确认本地库有可用账号（幂等，可重复跑；本地库与生产库是两套数据）
cd backend && npm run seed

# 3) 再起扩展开发服务器
npm run dev
```

本地后端**没跑**时，dev 版扩展的连接会直接失败（这正是想要的效果：**不会**悄悄打到生产）。

### 要回到生产怎么办

- **日常使用**：`npm run build` → `chrome://extensions` 重新加载 → 加载 `.output/chrome-mv3`。生产包读的是 `.env.production`，跟本地后端无关，**不需要**本地后端在跑。
- 从 dev 切回生产时，**记得把 dev 版扩展停用或删掉**，只留「限时特卖助手」（不带"开发版"）。

### 两个已知坑（切地址后连不上，多半是这两个）

**坑 1：storage 里的手动地址会盖过 env 默认值。**

`store.ts` 的 `setBackendUrl` 会把非默认地址持久化到 `browser.storage.local` 的 `backendUrl` 键；`checkAuthOnStartup` 读取时，**storage 的值优先于 env 默认值**。

→ 表现：改了 env、重新构建了，插件还是连旧地址（例如仍打生产，或本地后端起来了却连不上）。
→ 处理：清掉 storage 里的 `backendUrl`，再重新加载扩展。

```js
// 在扩展的 Service Worker 或弹窗控制台执行
chrome.storage.local.remove('backendUrl')
```

**坑 2：管理员设置页可以手动改地址，且以它为准。**

`AuthPanel.tsx` 里 `authUser.role === 'admin'` 时可见「后端服务地址」输入框，改一次就写进 storage。运行时手动值**优先于** env 默认值；两者冲突时以 storage 为准（同上，清掉即可）。非管理员看不到这个输入框，只会看到「测试连接」。

### 怎么验证改动生效了

```bash
# 生产包：应含 43.99.86.228，不含 localhost:5724/localhost:3000
grep -c "43.99.86.228"   .output/chrome-mv3/background.js
grep -c "localhost:5724" .output/chrome-mv3/background.js

# 开发包：结论应相反
grep -c "43.99.86.228"   .output/chrome-mv3-dev/background.js
grep -c "localhost:5724" .output/chrome-mv3-dev/background.js
```

> 注意：dev 版的**弹窗代码**不在磁盘 chunk 里，由开发服务器实时提供（`http://localhost:3000/entrypoints/popup/*.ts`）。要验证它，得趁 `npm run dev` 还开着时直接抓那个 URL。

## 环境变量清单

| 变量 | 作用 |
| --- | --- |
| `VITE_BACKEND_URL` | 后端主地址（构建时烤进产物） |
