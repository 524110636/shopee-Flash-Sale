# 02 架构总览

> **用途**：了解 popup／background／content／后端四者的分工，以及数据怎么流、消息怎么传、缓存怎么存。
> **何时读**：改跨层逻辑、排查「界面没反应」「进度丢了」类问题、需要理解某个状态从哪来。
> **来源**：原 `AGENTS.md` 的 Architecture／Data Flow／Message Protocol／Caching 段。

## 三层分工

扩展是 **Chrome MV3**，分三个独立运行环境，靠消息与 `storage` 通信：

| 层 | 文件 | 职责 | 运行时机 |
| --- | --- | --- | --- |
| **popup** | `entrypoints/popup/` | 界面 ＋ Zustand 状态机 ＋ 数据加载 | 用户点开扩展图标时；关掉即销毁 |
| **background** | `entrypoints/background.ts` | Service Worker：开卖循环、复制流程、alarm 调度、自动模式、消息中继、统计上报 | 常驻（但会被 Chrome 随时回收休眠） |
| **content** | `entrypoints/content.ts` | 注入卖家中心页面；统一悬浮进度面板；消息中继 | 卖家中心页面打开时 |
| **后端** | `backend/` | 账号、邀请码、试用、店铺绑定、防破解校验、统计 | 服务器常驻（PM2） |
| **管理网站** | `admin-web/` | 独立构建的管理员界面（用户／绑定／邀请码／统计），由后端托管在 `/admin/` | 管理员在浏览器打开时；**不进入扩展包** |

**管理网站与扩展的关系**：管理功能不在扩展里。popup 顶栏的「管理」按钮只是 `window.open()` 打开 `<后端地址>/admin/`；扩展不包含任何管理列表或写操作源码（旧的内嵌面板已移除）。依赖也完全独立——`admin-web` 用 React 18 + Ant Design 5，扩展用 React 19，两者不做版本统一。详见 [`11-配置与权限.md`](./11-配置与权限.md#独立管理网站admin-web)。

**popup 详情**（`entrypoints/popup/`）：
- `main.tsx` 把 `<App />` 挂到 `index.html` 的 root div；`index.html` viewport=420px
- `style.css` 只放 Tailwind 指令（`@tailwind base/components/utilities`）
- `App.tsx` 负责布局与条件面板切换（根级 `page` 决定功能首页 / 限时特卖工作页；工作页内用手动／自动页签切换；`copyMode='confirm'/'result'` 覆盖默认主界面）；管理入口与「无法打开管理网站」提示块位于**顶栏下方的公共区域**（不受店铺绑定状态／复制模式分支影响）
- `store.ts` 是 **Zustand 单一 store**，承载全部业务逻辑（含自动模式状态）
- `api.ts` 导出 `fetchProducts()` GraphQL 查询
- `types.ts` 定义所有共享 TypeScript 接口

**background 详情**：SPC_CDS Cookie 提取、开卖循环（`runEnableLoop`，用 `injectedFetch`）、复制流程（`EXECUTE_COPY`／`SCHEDULE_COPY`／`TRIGGER_SCHEDULED_COPY_NOW`）、自动模式（`START_AUTO_MODE`／`STOP_AUTO_MODE`／`GET_AUTO_MODE_STATUS`；alarms：`auto_mode_create`／`auto_mode_enable`／`auto_mode_heartbeat`）、消息中继。

**content 详情**：注入统一悬浮面板 `#__flash_sale_panel__`，把开卖进度、复制进度、自动模式状态合并到同一个容器。监听 `ENABLE_PROGRESS`／`ENABLE_COMPLETE`／`COPY_SCHEDULED`／`COPY_PROGRESS`／`COPY_COMPLETE`／`AUTO_MODE_UPDATE`。同时监听 `storage.onChanged` 作为消息失败时的备用路径（`_enableProgress`、`_copyCountdown`、`_autoModeStatus`）。

## 数据流

### 数据加载（在 popup）

```
用户输入 → App.tsx → store.ts actions → injectedFetch() →
  scripting.executeScript(MAIN world) → fetch() →
  响应 → store 状态更新 → React 重渲染
```

`injectedFetch()` 用 `scripting.executeScript({ world: 'MAIN' })` 把 fetch 注入页面主世界执行。**原因**：虾皮页面有 CSP，普通 `fetch` 打不通它的内部接口。

popup 版与 background 版的区别：
- **popup 版**：`tabs.query({ active: true, currentWindow: true })` —— 要求卖家标签页是当前激活页
- **background 版**：`tabs.query({ url: '*://seller.shopee.tw/*' })` —— 找任意卖家标签页，用户切到别的标签页也能继续跑

### 开卖循环（在 background）

```
Popup: 构建 items → storage.local(_enableParams) → 清旧 _enableProgress → isEnabling=true →
  START_ENABLE（fire-and-forget）→
  waitForBoot（storage.onChanged 等 _enableProgress.running=true，5s 超时 + 4s 重试）
Background: 重读 params → runEnableLoop() → 立即存进度 running=true →
  循环（在任意卖家标签页注入 fetch）→ storage.local(进度) →
  ENABLE_PROGRESS → runtime.sendMessage(popup) + tabs.sendMessage(content)
（popup 可关闭，循环继续；重开时 checkBackgroundStatus 直接读 _enableProgress）
```

### 复制限时特卖（在 background）

```
Popup: executeCopy() → 清 _copyTaskStatus → 发 EXECUTE_COPY（fire-and-forget）→
  waitForStorage() 监听 storage.onChanged('_copyTaskStatus')
Background: EXECUTE_COPY handler → 步骤1(关闭进行中活动) → 步骤2(取时段) →
  步骤3(建空活动) → 步骤4(本地保存数据) →
  存 _copyTaskStatus → storage.onChanged 触发 popup 完成
```

### 定时复制（两阶段 alarm）

```
阶段 1 — scheduled_copy alarm（活动开始前 5 分钟）：
  getSpcCdsFromCookies() → executeScheduledCopyFlow()（关闭进行中 → 取时段 → 建空活动 → 存数据）→
  存 _enableParams → 移除 _scheduledCopy → 建 scheduled_copy_enable alarm（活动开始后 5 分钟）
阶段 2 — scheduled_copy_enable alarm（活动开始后 5 分钟）：
  从 storage 读 _enableParams → getSpcCdsFromCookies() 刷新 SPC_CDS →
  runEnableLoop() → ENABLE_PROGRESS/ENABLE_COMPLETE 正常流转
```

**为什么分两阶段**：旧代码建完空活动立刻提交商品，活动未开始时 API 拒绝，全部 SKU 失败并触发零进展僵局检测而终止。

### `_copiedSaleData` 缓存验证

```
loadFlashSaleProducts(fsId) → 找到 _copiedSaleData 条目 →
  调 get_shop_flash_sale_item_id_list API → 用 Set 双向比对商品 ID →
  不一致：删条目 + 回退到正常 API 路径 | 一致：用缓存 →
  (v1.7.0) 之后一律再调 fetchProducts() GraphQL 刷新库存
```

### 自动模式（在 background）

```
START_AUTO_MODE: 验证场次 → 清残留状态 → 构建含 enableParams 的 status →
  logAutoMode → scheduleNextRound()
scheduleNextRound():
  调试模式：伪造 fakeTargetTime | 正常：找下一个场次（第一轮优先用选定场次）→
  phase='waiting_create' → 建 auto_mode_create alarm（targetTime - advanceMinutes）
auto_mode_create alarm: handleAutoModeCreate()
  关闭进行中活动 → 取时段 → 在 nextTargetTime 附近选最佳场次 →
  建空活动 → saveCopiedSaleData(新活动) → 存 status →
  logAutoMode → 建 auto_mode_enable alarm（targetTime + delayMinutes）
auto_mode_enable alarm: handleAutoModeEnable()
  GraphQL 刷新库存 → 同步到 _copiedSaleData →
  构建 EnableParams → runEnableLoop() → logAutoMode →
  sourceFlashSaleId = currentFlashSaleId（链式沿用）→ scheduleNextRound()
auto_mode_heartbeat alarm: sendAutoModeUpdate() → 同步到 popup/content
STOP_AUTO_MODE: 清 alarms + _enableParams + 存 stopped 状态 + 移除 _autoModeStatus
```

## 消息协议

| 方向 | 消息 |
| --- | --- |
| **Popup → Background** | `START_ENABLE`、`STOP_ENABLE`、`GET_ENABLE_STATUS`、`CLEAR_ENABLE_STATE`、`SPC_CDS_REQUEST`、`EXECUTE_COPY`、`SCHEDULE_COPY`、`TRIGGER_SCHEDULED_COPY_NOW`、`GET_TIME_SLOTS`、`GET_FLASH_SALE_ITEM_COUNT`、`CLOSE_FLASH_SALE`、`COPY_FLASH_SALE`、`APPLY_TEMPLATE_ITEMS`、`GET_SCHEDULED_STATUS`、`START_AUTO_MODE`、`STOP_AUTO_MODE`、`GET_AUTO_MODE_STATUS` |
| **Background → Popup** | `ENABLE_PROGRESS`、`ENABLE_COMPLETE`、`AUTO_MODE_UPDATE` |
| **Background → Content** | `ENABLE_PROGRESS`、`ENABLE_COMPLETE`、`COPY_SCHEDULED`、`COPY_PROGRESS`、`COPY_COMPLETE`、`AUTO_MODE_UPDATE` |
| **Content → Background** | `STOP_ENABLE`（通过进度面板的停止按钮） |

**基于 storage 的可靠通道**：`_copyTaskStatus`、`_enableProgress`、`_enableParams`、`_copyCountdown`、`_copiedSaleData`、`_autoModeStatus`、`_autoModeLogs`。当 `sendMessage` 响应不可靠（MV3 已知问题）时用它。content 的 `storage.onChanged` 监听 `_enableProgress`、`_copyCountdown`、`_autoModeStatus` 作为消息投递失败时的备用。

## 缓存

- 30 分钟缓存，存 `browser.storage.local` 的 `flashSaleCache` 键（类型见 `types.ts` 的 `CacheData`）
- 持久内容：`products`、`flashSaleList`、`flashSaleId`、`enableProgress`、`skuOverrides`、全局参数
- popup 打开时自动加载；抓取／开卖后自动保存
- 手动清除：「清除缓存」按钮（v1.6.4 起在底部「更多」折叠区），执行 `clearCache()` + `reset()` + `extractSpcCds()`

**storage 键命名约定**：下划线开头 = 内部状态（`_enableProgress`、`_copiedSaleData`）；无前缀 = 可缓存数据（`flashSaleCache`）。**原因**：`clearCache()` 只清后者；混用会导致清缓存把正在跑的进度一起抹掉。

## 虾皮接口速查

- **GraphQL**：`POST /api/marketing/v4/graphql/query/` —— 商品／SKU 详情（查询语句在 `api.ts` 的 `PRODUCTS_QUERY`）
- **限时特卖**：`/api/marketing/v4/shop_flash_sale/{get_shop_flash_sale_list, get_shop_flash_sale_item_id_list, set_shop_flash_sale_items, set_shop_flash_sale, get_time_slot_id, get_shop_flash_sale_item}`
- **必需请求头**：`sc-fe-session`（CSRF token，从页面 DOM／window 提取）
- **必需请求体字段**：`use_global_category: true` —— 缺这个会报 code 1001
- **价格规则**：必须是整数，且严格小于原价
