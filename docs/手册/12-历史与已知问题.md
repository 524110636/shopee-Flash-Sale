## 已知问题

### 即时复制后偶发仍显示源活动

复制创建新活动成功后 `flashSaleId` 已切换为新 ID（`set({ flashSaleId: newId })`），但在频繁创建/删除活动的场景下偶发仍显示源活动。

**怀疑原因**：虾皮服务端缓存/CDN 不一致导致 `get_shop_flash_sale_list` API 短时间内返回不稳定结果。

**状态**：需等虾皮系统稳定后重新复现。若确认是服务端问题，需考虑更激进的重试+去重策略（如合并本地 `_copiedSaleData` 到列表中）。

### 生产包里仍保留调试入口

| 位置 | 内容 |
| --- | --- |
| `App.tsx`（向导 `selecting_flash_sale` 阶段） | 向导「调试: 立即创建并提交（跳过等待）」 |
| `components/product/AutoModePanel.tsx` | 自动模式「⏩ 加速调试模式」 |

**风险**：用户误点会立即在真实店铺创建活动并提交商品，跳过所有时间校验。
