# 限时特卖助手 — 项目手册索引

> 用途：把「一份 700 行的文档」拆成「必要红线＋按任务取用的手册」。
> 本目录由 `2026-10-12-02 入口与手册拆分` 任务建立，正文自 `AGENTS.md`、`CLAUDE.md`、`运维速查.md` 迁入。
> **阅读方式：按任务只读需要的那一份，不要一次读完整套。**

## 阅读方式

1. 先读根目录入口（`AGENTS.md` 或 `CLAUDE.md`）——那里有工作目录、开工必读三件套、必要红线摘要。
2. 按下面的「按任务导航」找到对应手册，只读那一份。
3. 手册给的是**规则与实现指针**（符号名、文件、既有原因），不是完整源码；改代码前仍要打开源码确认。

不在入口使用 `@文件` 自动导入，也不通过 hook 拼进正文——避免每次对话都把整套手册塞进上下文。

## 现行与历史的区别

手册内容分四类，读之前先看它属于哪一类：

| 类别 | 含义 | 遇到冲突时 |
| --- | --- | --- |
| **现行约束** | 必须怎么做，且带具体原因 | 必须遵守；确实要改先解释影响 |
| **技术事实／参考** | 接口格式、字段、目录等客观情况 | 以实测源码为准 |
| **设计决策** | 当初的选择与背景 | 可讨论，但不自动升格为硬规定 |
| **历史** | 旧版本、旧快照、已过时结论 | **不能**当作当前状态，引用前核实 |

根目录 `SESSION_CONTEXT.md` 是 2026-05 历史快照，其中的路径与待办已经过时，只作排查线索。
`PROJECT_STATUS.md` 是唯一进度表，与其他文档冲突时以它为准。

## 维护方法

- **新增或修改现行约束时**：在对应手册里写清「要求＋为什么」，只写要求不写原因视为未完成。
- **改了源码里的符号名、字段名、文件位置**：同步更新相关手册，**不要写死行号**（行号必然漂移，用符号名或段落标识）。
- **红线只增不减要谨慎**：不是所有技术事实都是红线；只有「做错会出事」的才进 `01-红线.md`。
- **入口保持精简**：入口约 80–120 行，只放红线摘要与导航；正文一律进手册。
