# 07 前端与状态

> **用途**：store 状态形状、类型定义、向导流程、模板系统、SKU 编辑、登录门、悬浮面板。
> **何时读**：改 popup 界面与状态、加字段、改向导步骤、排查「界面不刷新」「状态丢了」类问题。
> **来源**：原 `AGENTS.md` 的 State Shape／Template System／Content Script Progress UI／Type Definitions／Login Gate ＋ `CLAUDE.md` 的 Login Gate／Important Patterns。

## store 状态形状

全部业务逻辑在 `entrypoints/popup/store.ts` 的**单一 Zustand store**。状态分组：

| 分组 | 字段 |
| --- | --- |
| **SPC_CDS** | `spcCds`、`spcCdsVer`、`isConnected`、`isExtracting` |
| **店铺信息**（来自登录 API） | `shopId`、`accountId`、`shopUsername` |
| **商品** | `productIds[]`、`products[]`、`inputText`、`isLoading`、`error` |
| **限时特卖** | `flashSaleList[]`、`flashSaleId`、`flashSaleInfo`、`isLoadingFlashSales` |
| **开卖参数** | `maxRetries`、`infiniteRetry`、`discountRate`、`flashSaleStock`、`purchaseLimit`、`isEnabling`、`enableProgress` |
| **复制** | `copySource`（flashSale + itemCount）、`copyMode`、`copyTaskStatus`、`isCopying`、`savedTemplates[]`、`selectedTemplate`、`hasScheduledCopy`、`scheduledTaskStatus` |
| **1 天备货 SKU** | `oneDaySkuSelectedIds[]`、`oneDaySkuFlow`（phase／running／currentIndex／total／message／error／items[]／canStartFlashSale） |
| **首次使用** | `firstUse`（open／loading／products[]／selectedIds／searchKeyword／searchResults[]／fetchedTotal／hasMore／cursor） |
| **SKU 覆盖** | `skuOverrides: Record<string, SkuOverride>`，键为 `${itemId}-${modelId}`（字段：`discountRate?`、`promoPrice?`、`stock?`、`purchaseLimit?`） |
| **自动模式** | `autoModeActive`、`autoModeStatus`、`autoModeLogs`、`firstSelectedActivity`、`showAutoModeUpgradeModal` |

> 文档旧述把自动模式字段写成 `autoModeView`／`autoModeConfig`，**实测不存在**；真实字段以上表为准（对应 `store.ts` 中 `AppState` 的自动模式字段段）。

**为什么集中在一个 store**：同一份状态被多个面板（主界面／自动模式／向导）读写，若各组件各存一份，会出现「这边改了那边不刷新」；集中一处才能保证关弹窗再开、进度不丢。

**动作全内联的原因**：动作全定义在 `create<AppState>((set, get) => ({...}))` 内，才能让 `set`／`get` 直接访问同一份状态；拆到外部模块容易出现「读的是旧快照」，表现为界面不更新。

**为什么所有类型集中一份**：popup／background／content 是三个独立运行环境，靠同一份类型定义才能保证消息契约不写错；分散定义会出现一边改了另一边不知道。

## 向导流程

「一键修复商品并开启特卖」的向导阶段：

```
idle
→ preparing_sku / publishing_product / searching_discount / removing_discount / restoring_discount
   （这些阶段在 UI 上都显示为「优化中」）
→ editing_params          ← 修复完成，用户确认参数
→ selecting_flash_sale    ← 选择已有活动 或 创建新活动
→ starting_flash_sale     ← 提交
→ success / failed
```

### `editing_params`（修复完成）

展示修复成功的商品卡片（可点击编辑 SKU / 全局参数）。商品卡片列表下方、全局参数上方显示绿色引导：

> 修复完成，请点击上方商品列表修改限时特卖商品价格，库存，限购等信息(默认参数是你的折扣信息。)，然后点击下一步：选择限时特卖。

**为什么**：修复后折扣率已自动同步为实际值，但用户可能还想调价格/库存；不引导的话用户直接下一步，用的就是默认值。

### `selecting_flash_sale`（选择目标）

列出已有进行中/即将开始的活动，每个带「定时」与「加入」按钮；下方是时段选择（通过 `fetchTimeSlots` 获取）用于创建新活动。

顶部有两个时间输入框：
- `wizardAdvanceMin` —— 提前 N 分钟创建空活动
- `wizardDelayMin` —— 活动开始后 N 分钟提交商品

时段列表用 radio 选中模式 + 统一「开始」按钮。

### 三条提交路径

| 路径 | 函数 | 行为 |
| --- | --- | --- |
| 加入已有活动 | `addToExistingFlashSale` | 构建 enable items（含 `item_display_image` 从 `p.images?.[0]`、`stock` 上限 `Math.min`、零库存过滤、未打折 SKU 检测、活动结束检查）→ 存 `_enableParams` → 发 `START_ENABLE` → **走 Background `runEnableLoop`**（与手动模式一致的多轮重试与错误处理） |
| 新建活动（可定时） | `createNewFlashSaleAndAdd` | 两阶段：`advanceMin > 0` 时发 `SCHEDULE_WIZARD_FLOW` 给 background 定时创建（`wizard_create` alarm），再由 `scheduled_enable` alarm 定时提交；`advanceMin = 0` 时立即创建 |
| 定时加入已有活动 | `scheduleEnableForFlashSale` | 发 `SCHEDULE_ENABLE` 给 background → `scheduled_enable` alarm |

空活动的商品展示由 `_pendingFlashSaleData`（内存）与 `_copiedSaleData`（storage）预填。

### 调试按钮

`App.tsx` 的 `selecting_flash_sale` 阶段有「调试: 立即创建并提交（跳过等待）」按钮，传 `now` 作为 `slotStartTime` 并设 `advanceMin=delayMin=0`，强制立即创建 + 提交。该路径调用 `validateShopAccess(spcCds, 'wizard_flow')` 拦截试用到期用户。

> ⚠️ 这个调试按钮**仍在生产包里**（见 [`12-历史与已知问题.md`](./12-历史与已知问题.md#已知问题)）。

### 防重复点击

`selecting_flash_sale` 阶段的「立即加入」「定时」「开始」「调试」按钮：

```
disabled={isEnabling || oneDaySkuFlow.running || !!oneDaySkuFlow.message}
```

store 层 `addToExistingFlashSale`、`scheduleEnableForFlashSale`、`createNewFlashSaleAndAdd` 入口也有防重入守卫：

```
if (state.isEnabling || oneDaySkuFlow.running || oneDaySkuFlow.message) return
```

`goToFlashSaleSelection` 清除 `message` 和 `error`，防止引导文案「请选择目标限时特卖场次」误触发按钮禁用。

**为什么**：这些操作会创建真实的店铺活动，重复触发会建出重复活动。

## 首次使用流程

1. `FirstUseWarningModal` 先弹出（除非用户勾选「以后不再提示」，持久化在 `_firstUseWarningDismissed` storage 键），提醒用户在插件前**先把商品从其他促销活动移除**（多件优惠、免运、套装、加购），折扣活动除外
2. 确认后 `FirstUseModal` 打开
3. `FirstUseModal` 通过 `search_product_list` API（分页，`fetchShopProductsPage`）获取店铺全部商品，**每页 12 个、按销量从多到少排序**，支持关键词搜索
4. 用户勾选最多 **20** 个商品
5. 触发 `runFirstUseFlow`：把 `ShopProductListItem[]` 转成 `ShopeeProduct[]`（`modelList` 为空），设置 `oneDaySkuSelectedIds`，自动调用 `runOneDaySkuAndEnable`

`getHighestModelPrice()` 接受可选 `productInfoModels` 参数 —— 用于 `ShopeeProduct.modelList` 为空时（首次使用场景）从 `product_info.model_list` 取价格。

**为什么必须先移除其他促销**：叠加促销会让价格计算异常、发布被拒或产生非预期售价。

## 模板系统

- 保存/加载完整配置（折扣率、库存、限购、SKU 覆盖）
- 应用时的商品比对：黄色提示被移除的商品，蓝色提示新增的商品
- 模板存 `browser.storage.local` 的 `flashSaleTemplates` 键

### 导出

每个模板行有蓝色「导出」按钮，下载 JSON：

```json
{ "version": 1, "type": "flash_sale_template", "name": "...", "exportedAt": "...",
  "data": { "discountRate": 60, "flashSaleStock": 200, "purchaseLimit": 0,
            "skuOverrides": {}, "productInfo": [] } }
```

### 导入

空闲状态的「导入模板」按钮打开文件选择器，校验 JSON 格式（检查 `version`、`type`、`data` 字段），通过 `importTemplate` store action 保存。支持任意实例导出的 `.json`。

### 编辑

每个模板行的「编辑」按钮打开 `TemplateEditDialog`：

- 显示全局参数（折扣率%、活动库存、限购数量）与按 Item ID 分组的 SKU 覆盖
- 父行：▶/▼ 折叠开关、商品名、SKU 数、行内「Model ID + +SKU」快捷添加
- 展开的子行：折扣%、限时价、活动库存、限购数量可编辑 + 「移除」按钮
- 支持「全部展开/收起」（当前页）
- 每页 8 个 Item ID，带 ‹上一页/下一页›
- 底栏显示商品总数 + SKU 总数
- 保存调 `updateTemplate`

`updateTemplate(name, Partial<FlashSaleTemplate>)`：读 `flashSaleTemplates` → 找已有模板 → 合并字段（保留 `name`／`createdAt`，自动设 `updatedAt`）→ 写回。与 `importTemplate`（全量替换）不同，只改传入字段。

### 分组与分页实现

数据加载时把 `skuOverrides` 按 `itemId` 分组为 `ItemGroup[]`（`itemId`、`productName`、`models[]`），排序后分页（`PAGE_SIZE=8`）。展开状态用 `Set<string>` 追踪，`useMemo` 算当前页。新增 SKU 时自动加入展开集合并按 `modelId` 排序；删除最后一个 SKU 时自动移除整组。

### `enterCopyMode` 不再自动选模板

`selectedTemplate` 默认 `null`，用户需手动选择。

**为什么**：旧代码 `selectedTemplate: names[0]` 自动选第一个模板，其 `discountRate=60`／`flashSaleStock=200` 等默认值会进入 `executeCopy` → 存到 `_copiedSaleData`，导致加载复制活动时全局输入框显示模板默认值而非实际 flash sale 配置。

## SKU 编辑

### 四个可编辑列

| 列 | 写入字段 | 互斥规则 |
| --- | --- | --- |
| 折扣% | `discountRate` | 写入时**清空** `promoPrice` |
| 限时价 | `promoPrice` | 写入时**只存** `promoPrice`，不反算折扣率 |
| 活动库存 | `stock` | 保留 `discountRate`、`promoPrice` |
| 限购数量 | `purchaseLimit` | 保留 `discountRate`、`promoPrice` |

**每个 `onChange`／`onBlur` 必须保留所有其他字段。** 这是硬约束，详见 [`01-红线.md`](./01-红线.md#sku-编辑必须保留其他字段)。

### 批量编辑框

表格上方有浅蓝底批量编辑行：`折扣% | 活动库存 | 限时价 | 限购数量`。输入后 `onBlur` 或 `Enter` 应用到当前商品**所有** SKU。限时价批量编辑时同步清空折扣%字段（互斥设计）。手动模式与自动模式都适用。

### `onEdit` 回调

可选 prop，任何用户触发的 `onChange`／`onBlur` 修改都会调用。用于 `AutoModePanel` 的动态「已编辑」标记机制，不影响手动模式现有行为。

### `key` prop 现状

`<SkuTable>` 共 **6 处**渲染点，其中 **4 处**带 `key`：

| 位置 | 带 key |
| --- | --- |
| `App.tsx`（向导编辑 SkuTable） | ✅ |
| `App.tsx`（覆盖详情 SkuTable） | ✅ |
| `components/product/CopyConfirmPanel.tsx` | ✅ |
| `components/product/ProductList.tsx` | ✅ |
| `components/product/AutoModePanel.tsx` | ❌ |
| `components/product/ProductViewModal.tsx` | ❌ |

带 key 时切换商品 React 会销毁旧实例创建新实例，内部 `priceEditValues` 状态归零；缺 key 时可能残留旧商品编辑值覆盖新商品字段。后两处未加是当前实际状态（非笔误），改动那里时要留意状态残留。

### 覆盖持久化

`setSkuOverride` 每次编辑后自动调 `saveCache()`，把 `skuOverrides` 持久化到 `flashSaleCache`。

**为什么**：它早期只更新 Zustand 内存状态，关掉 popup 后编辑就丢了（下次打开时 `loadCache` 加载的是旧缓存）。

### 字段保留的来源提示

SKU 输入框 `placeholder` 显示全局默认值，用于区分「用全局默认」与「手动输入过」。

## 登录门

`App.tsx` 的门控顺序：

| 条件 | 表现 |
| --- | --- |
| `isCheckingAuth` | 加载 spinner |
| `!isLoggedIn` | 全屏 `AuthPanel`（登录/注册） |
| `!storeBindingsLoaded` | spinner「正在加载店铺信息...」 |
| 已登录但无绑定 | 阻断信息「请先绑定店铺」，或 `storeBindingsError` 时显示红底错误卡 + 重试按钮 |
| 已登录 + 有绑定 + 当前店铺 `SPC_CDS`／`shop_id` 不在绑定中 | 琥珀色「当前店铺未绑定」提示（**不再是硬阻断**，引导用户点绑定按钮） |
| 管理员 | 不进管理面板，改由顶栏「管理」按钮打开独立管理网站；门控提示照常显示 |

`isCurrentStoreBound`：**先比 `shopId`**，旧记录回退比 `spcCds`。

**诊断日志**：`store.ts` 用 `[init]` 前缀追踪 `checkAuthOnStartup`／`refreshStoreBindings` 路径；`App.tsx` 用 `[render]` 前缀追踪渲染门状态变化（受 `VITE_DEBUG_LOGS` 控制）。

### 管理员入口

顶栏「管理」按钮只在 `backendApi.isAdmin()` 为真且不在自动模式时渲染，点击调用 `App.tsx` 的 `openAdminSite()`：打开 `<getBaseUrl()>/admin/` 新标签页。

- 后端地址为空 → 不打开页面，`adminSiteNotice` 显示「未配置后端地址，无法打开管理网站」
- `window.open` 返回 null（被拦截）→ 提示里带上完整地址供手动复制
- **不做生产地址回落**：地址只来自用户在设置里配置的值／构建期默认值

**提示必须渲染在顶栏下方、翻转容器之前**。按钮在公共顶栏，提示块若放进下面的内容分支，在「请先绑定店铺」「当前店铺未绑定」等状态下不会渲染 —— 管理员点按钮会看到"什么都没发生"。规划方 6.5 复现的正是这一场景。

**为什么这么做**：旧内嵌面板已移除，管理功能全部由独立网站承载；扩展里不再保留任何管理列表或写操作源码。

**注意**：`App.tsx` 的三个门控（未绑定店铺 / 正在同步绑定 / 当前店铺未绑定）**不再**为管理员放行 —— 管理员也能正常看到这些提示，管理入口只走顶栏按钮。

### `checkAuthOnStartup` 竞态修复

原 `setTimeout(() => refreshStoreBindings(), 500)` 改为 `await refreshStoreBindings()`。

**为什么**：消除 500ms 窗口期中 `isLoggedIn=true` 但 `storeBindings=[]` 的状态，防止用户快速点「绑定当前店铺」造成重复绑定。

### `storeBindingsLoaded` 门控

新增该标志，在店铺信息加载完成前显示 spinner，避免慢网络下先闪一下「未绑定」界面。

### 设置页安全

`AuthPanel` 设置视图中的后端地址输入框**仅在 `authUser.role === 'admin'` 时显示**。普通用户只看到「测试连接」按钮（调 `healthCheck()`）；成功显示绿色「后端连接正常」，失败显示红色错误详情。未登录状态下同样隐藏地址输入框。

## 悬浮面板

统一面板 `#__flash_sale_panel__`，含三个区段：

| 区段 | 变量 | 内容 |
| --- | --- | --- |
| 自动模式 | `autoSectionEl` | 运行状态、倒计时 |
| 开卖进度 | `progressSectionEl` | 成功/失败数、轮次、进度条、停止按钮（由 `buildProgressSection()` 懒构建） |
| 复制 | `copySectionEl` | 定时倒计时、步骤进度 |

旧的 `createProgressUI()`（会销毁其他区段）已移除。`showComplete()` 完成后 3s 自动隐藏进度区段；仅当没有其他区段可见时才移除整个面板。手动开卖、向导开卖、自动模式**共用同一个面板**。

样式：半透明 + `backdrop-filter` 模糊。

**陈旧 DOM 清理**：`createPanel()` 在创建前先移除残留的 `#__flash_sale_panel__`。

**storage 备用**：初始化时从 storage 读 `_enableProgress` 与 `_copyCountdown`，不等消息就能显示 UI；`storage.onChanged` 监听器在消息丢失时实时更新。

### 自动模式实时倒计时

`renderAutoSection()` 渲染 `#__auto_countdown__` 元素，`updateAutoCountdown()` 每秒更新，显示距 `nextActionTime`（操作触发时间）或 `nextTargetTime`（场次开始时间）的剩余分钟:秒。自动模式停止时自动清除计时器。

### 最小化/恢复

统一面板与复制 UI 都有 `−` 最小化按钮（右上角）：

- `toggleMinimize()`／`toggleCopyMinimize()` 把面板收缩为右侧窄条，只显示 `◀` 箭头 + 一行倒计时/状态摘要
- 点击箭头还原
- `panelMinimized`／`copyMinimized` 标志跟踪状态
- `updateMinimizedContent()`／`updateCopyMinimizedContent()` 刷新收缩内容
- `toggleMinimize()` 保存/恢复 `wasCopyVisible`、`wasAutoVisible`、`wasProgressVisible`，防止展开后复制区段保持隐藏

### 失败详情图片

`renderFailedDetails()` 用 `normalizeImageUrl()` 给虾皮返回的原始图片 ID（如 `tw-11134207-820l6-mna42fatmeiqd7_tn`）补上 `https://cf.shopee.tw/file/` 前缀。函数兼容已有完整 URL（`http://`、`https://`、`data:` 开头原样返回）。

**为什么**：漏拼前缀时限时特卖列表全是**裂图**，用户以为商品图丢了、不敢开卖。

### `showComplete()` 初始化

`showComplete()` 先调 `createPanel()` + `buildProgressSection()` 再检查 `headerEl`。

**为什么**：`ENABLE_COMPLETE` 可能在 `ENABLE_PROGRESS` 之前到达（零商品或立即出错），先检查 `headerEl` 会静默返回不显示任何面板。

## 界面约定

### 按钮颜色语义（四色体系）

| 颜色 | 用途 | 例 |
| --- | --- | --- |
| 蓝色 outline | 普通操作 | 查看、刷新、复制、导入/加载模板 |
| 绿色实心 | 主确认 | 开启限时特卖、创建复制任务、保存模板 |
| 红色 outline | 停止/危险 | 停止、清除缓存 |
| 灰色 | 次要/取消 | 取消、关闭 |

hover 规则：`hover:bg-{color}-50 hover:text-{color}-600 hover:border-{color}-300`。

**危险操作禁止用蓝色** —— 颜色是唯一的操作后果提示。

### 异步按钮统一反馈

所有触发异步操作的按钮：点击后 100ms 内文案切换为 loading（「加载中」「清除中」「执行中」），`disabled` 防重复点击，请求完成后 `finally` 恢复。

涉及按钮：清除缓存、停止、手动触发定时任务、应用模板、删除模板、保存模板。

**两个例外**：
- **重新获取 SPC_CDS** —— 用 store 的 `isExtracting` 状态，**不套局部 loading**
- **开启限时特卖** —— 通过按钮切换（🚀 开启 → ⏹ 停止）提供反馈

**禁止在 loading 期间允许点击。**

**为什么**：不等反馈，用户会以为没点上而反复点，导致重复提交。

### 布局信息分层

主界面按优先级分三层：

1. **首屏**：当前活动上下文条 + 定时任务状态卡，置于 Header 正下方
2. **中层**：活动列表（紧凑折叠头）+ 商品列表 + 开启限时特卖参数区连为一体
3. **底层**：「更多」折叠区（`<details>`）收纳低频功能：商品 ID 输入、获取商品信息、加载列表、模板管理、手动触发定时任务、清除缓存

原有的两个独立折叠区（「高级操作」+「商品ID区」）已合并为单一「更多」入口。

> **设计历史 vs 当前实际**：文档旧述称折叠区摘要文字是「高级操作」且「仅在 `isConnected` 为 true 时渲染」。当前实际摘要文字是「**更多**」，且**未使用** `isConnected` 门控 —— 以源码为准。当时的门控设计原意不再追溯（详见 [`08-关键设计决策.md#决策-22`](./08-关键设计决策.md#决策-22--低频操作折叠v163)）。

### 活动上下文展示条

`Separator` 后渲染，显示条件 `flashSaleId && !copyMode`。从 `flashSaleList` 查找当前活动，`name` 为空时回退 `活动 #{id}`，status 按时间判断为「即将开始/进行中/已结束」。

样式用**品牌 token**（`bg-shopee-brand-light border border-shopee-brand/15` 等），文案不含「当前活动：」前缀，直接展示 `{name} · MM/DD HH:mm ~ HH:mm · {status} · N 个商品`。

### 引导条与复制按钮

- **引导条**：活动列表展示、且**没有**定时任务或进行中的复制时，显示一条**品牌色**信息条，提示用户点「复制」按钮。
- **复制按钮样式**：活动列表里的「复制」按钮用**实心品牌色**（`bg-shopee-brand text-white`），不是 outline；新建的活动额外带「**新/待开启**」badge。

**为什么**：复制是这个工具最常用的入口，但用户第一次打开时不一定知道要点哪里；实心色 + 引导条是把它推到视野里。

### 复制流程步骤提示

`CopyConfirmPanel` 顶部三步提示：`● 选择源活动 → ● 选择目标时间 → ○ 创建复制任务`。前两步加粗（已完成），第三步灰色（待确认）。纯展示，不控制流程。

### 错误提示就近化

`CopyConfirmPanel` 用局部 `viewError` 状态，失败时红色文字紧邻「查看」按钮显示。其他 inline 提示已存在：`applyMessage`（应用模板）、`saveSuccess`（保存模板）、`importMessage`（导入模板）、`slotsError`（时段选择）。

**为什么**：远程错误提示（页面顶部）在长列表里容易看不见，用户以为没反应。

### 主题色

主色调是 **Teal**（`#0D9488`）。CSS 变量全为 teal HSL（hue 173）；`tailwind.config.ts` 定义 `shopee-brand`／`brand-dark`／`brand-light`。所有组件引用 `brand`。

历史：早期用虾皮橙 `#EE4D2D`，v1.8.0 改为 teal。旧的 `border-l-blue-500 bg-blue-50/50` 等工具类已不再使用（部分文档仍写着，属历史残留）。

### 「使用说明」与「定制开发」

- 非管理员用户右上角有「使用说明」按钮，用 `window.open()` 打开飞书用户手册
- 旁边是渐变「定制开发」按钮（orange-400 → amber-500），点击弹出介绍虾皮定制开发服务的模态窗口
- 该模态窗口的联系区有「查看二维码」按钮，用 `browser.runtime.getURL()` 打开 `public/contact-qr.png`（作者微信二维码）的居中浮层
