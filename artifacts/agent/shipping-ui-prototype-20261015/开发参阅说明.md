# 备货定时切换界面原型 V3：正式开发参阅

日期：2026-10-15。当前正式业务要求以原08任务书**第31节**为准。用户已明确选择**仅执行一次**；V1／V2中的每天、每周、自动推进下一轮和“暂停循环”均已撤回，不属于本轮。历史图／原型只供追溯。

## 如何查看

双击「备货循环界面原型.html」离线打开，文件名为保留旧链接沿用，页面标题已经改为「备货时间定时切换」。也可使用 http://127.0.0.1:5790/备货循环界面原型.html?v=3 。不需后台服务，HTML不发网络请求、不读取账号或写入持久状态，不创建任务。点击确认／撤销只演示未开始任务的状态。

## 用户已确定的界面

1. 三步独立卡片：设置常规备货天数 → 安排切换时间 → 确认本次安排；模块间距20px，主容器最大600px。落地适配现有500px弹窗，390px宽度无横向滚动。
2. 常规备货天数使用原生下拉框，整数2–10天；切现货固定1天。图中8天是样例，真实默认值优先复用用户已有选择。
3. 开始与恢复日期／时间均由用户决定；跨天标识次日／间隔天数；执行方式为不可修改的「单次执行」。完整执行一次“切1天→恢复常规天数”后结束，不自动安排下一周。
4. 主按钮「确认并安排任务」，顶部真实状态及下一次动作清楚可见。等待开始阶段可撤销；再次安排复用同一店铺上次的天数、时刻、排除商品和物流设置，日期重新选择、再次确认。
5. 排除商品只在主页面保留「设定排除商品」按钮和已排除数量，点击打开二级原生模态弹窗。弹窗支持商品ID检索、任意多选、销量降序、快捷勾选全店销量前5／前10、全选检索结果、清空、取消／确认。快捷勾选保留已选并去重、不受检索限制；未知销量不冒充0，同销量按ID稳定排序。确认才提交，取消／Escape不改变已确认选择。快捷选择固定商品ID，不随未来销量自动改选。本次两阶段都排除同一组ID。
6. 主流程中的浅暖色提示卡：建议尽量周末使用，避免其他时段；执行期间保持设备开机、浏览器运行并联网。日期不锁死周末，周末不保证不中断；关机／断网处理明细折叠。
7. HTML的立即修改页签只说明复用边界，不是要求把正式手动页做成占位页；正式产品须保留既有完整手动修改流程和结果。

## 单次任务运行规则

未来日期保存后，中途重启或断网不丢设置；浏览器启动先恢复本地计划检查，联网后核实身份权限。首次切1天有最多5分钟正常调度容差，且必须早于恢复时间；超过则本次已错过、零补切。已确认切1天的商品保留恢复义务，恢复时刻前重新上线仍等待原时间，已过恢复时刻则核实后优先恢复常规天数。结果不明先核实，仍不明提示处理，不盲目重发。任务书第31节详细定义撤销、截止和恢复集合。

设备关机或浏览器完全退出期间不能按时执行；本轮不做云端、开机自启或新的保活系统。恢复备货天数与恢复物流渠道是不同义务，都不得丢失。物流只在每次批改时临时关闭／恢复，不能在两次修改之间持续关闭。

## 开发参照方法

以当前HTML的DOM层级、CSS变量和交互为外观参照，截图辅助对照。把结构映射到现有React组件，不能把HTML的演示脚本作为真实执行器拷进popup。真实保存成功、下一动作、运行、恢复、等待登录、结果未知等状态必须来自background持久记录；HTML的启用／撤销模拟不代表真实商品已修改。现已通过42项本地原型检查，不等于产品新逻辑已完成。
