## 1. 覆盖范围与事实等级

根`manifest.json`指定`popup.html`、`background/main.js`、`content.js`及特卖页`flash-sale-delete-clean.js`。交叉盘点5张popup主工具卡、12个dashboard页签、4个shipping页签、topup规则页、content浮窗、Express路由与Vue管理页。源码存在且有调用链标「静态接通」，部署／用户包／接口实时可用都未测试。文档与代码矛盾以代码为依据并留记录。

源background约1.19 MB、dashboard约0.60 MB；调查没有将混淆死代码或反调试、构建副本当成需要迁移的产品功能。源根版本1.0.2和当前目标1.15.2是不同产品版本，不能直接大小比较决定升级。

## 2. 特卖相关（M01）

### 旧自动续期

`popup.js:startAutoTopup/stopAutoTopup`消息 → `topupLoopManager.startFlashSaleAutoTopup/executeFlashSaleProcess/processFlashSaleRenewal/continueFlashSaleRenewal`。storage `autoTopupEnabled`，alarm `flashsale_autoTopup`6分钟；剩余不足约10分钟进入续期，先保存pending、关旧场、取档位、建新场，30秒后加商品。旧场关闭失败可通过`flash-sale-delete-clean.js`重试并回报`flashSaleCloseRetrySuccess`；建新失败pending最多10次；设置商品失败尝试清新空场。

| 方法与完整路径 | 核心字段／含义 |
| --- | --- |
| GET `/api/marketing/v4/shop_flash_sale/get_shop_flash_sale_list/` | `offset/limit/type`，当前活动列表 |
| GET `.../get_shop_flash_sale_item/`、`.../get_shop_flash_sale_item_id_list/` | `flash_sale_id`，商品／model明细和ID |
| GET `.../get_time_slot_id/` | `start_time/end_time`，平台时段 |
| POST `.../set_shop_flash_sale/` | 关旧：`flash_sale_id,time_slot_id,status:2`；建新：`time_slot_id` |
| POST `.../set_shop_flash_sale_items/` | `flash_sale_id,items,use_global_category:true`；items含`item_id/model_id/input_promo_price/stock/purchase_limit/status` |

与FS_MODE通过`GET/SET_FSMODE_ACTIVE_MODE`互斥。将其“续期”和目标“按轮数自动模式”视为不同用户触发语义，比较后再决定是否补入口。

### FS_MODE手动、自动、资格修复与诊断

`dashboard.js`的`FS_MODE_MODULE`、后台`flashSaleModeManager`。消息`START/STOP_FSMODE_ENABLE`、`GET_FSMODE_ENABLE_PROGRESS`、`START/STOP_FSMODE_AUTO`、`GET_FSMODE_AUTO_STATUS`。手动可以选未来档位（提前建／延时提交）或填写既有活动ID；自动按轮数／天数，参数`mode/value/advanceMinutes/delayMinutes/selectedSlotId/selectedSlotTime/enableParams`。后台alarms `fsmode_create/fsmode_enable/fsmode_heartbeat`；状态`fsmodeJob/fsmodeEnableJob/fsmodeEnableProgress/fsmodeSaleData`，日志`fsmodeLogs`上限500。

商品GraphQL POST `/api/marketing/v4/graphql/query/`成功是`data.products.items`且无`errors[]`，不能要求REST `code=0`。SKU加入写接口见上表；源循环处理10010硬错误、库存不足减半、每3轮刷新Cookie、10轮无进展／低失败终止。UI调价、库存、限购、全局参数与逐SKU覆盖要保留来源关系。

资格修复是`dashboard.js:runForgeFlow/forgeEligibility`页面侧逐商品执行，目标已有后台runner不回退。主要REST：GET `/api/v3/product/get_product_info` → POST `/api/marketing/v3/public/discount/search/`（`discount_type:0,time_status:0,keyword:productId,search_type:2`）→ POST `/api/marketing/v4/discount/delete_abnormal_seller_discount_items/`（`promotion_id,item_id_list`）→ POST `/api/v3/product/update_product_info`（`product_id,product_info,is_draft:false`）→ POST `/api/marketing/v4/discount/update_seller_discount_items/`（`promotion_id,discount_model_list`）。专用SKU名「批發客戶下訂-請勿下單」、组合≤100、目标1天；源任意已有1天SKU会跳过；折扣价使用源单位转换，不能混用特卖价单位。

源`fsmodeForgeBackup_<productId>`备份存在凭据相关字段；迁移只保留恢复所需业务数据，运行凭据即时取Cookie，保护目标已有身份规则。折扣移除失败不发布；发布成功但折扣恢复失败需报部分完成，保留可读恢复义务；源由用户手动重试恢复。高级诊断含可能建／关活动的写操作，模拟模式与真实诊断不可混写。

## 5. 预算控制台（M04）

`topup.html/js`→`START_BUDGET_TOPUP_RULES_LOOP/STOP_BUDGET_TOPUP_RULES_LOOP/REQ_TOPUP_PANEL_DATA/REMOVE_MONITOR_ITEM/QUERY_AD_ITEMS`→`TopupManager`。规则包括商品ID、加额、水位/区间、最高预算、默认预算、延迟、查询频率、重复、CPC/ROI约束、执行时间窗、23:30暂停/预算重置、定时恢复及ROI提高/恢复。状态过滤UI“全部”禁用，当前默认只看进行中。

storage包含`topupLoopJobCache/topupLoopJob/topupPanelData`；alarms `BUDGET_TOPUP_LOOP`、`BUDGET_TOPUP_ITEM::<itemId>`、`RESET_DEFAULT_BUDGETS`等。轮询依据各rule频率节流，命中后延迟执行前重查当前campaign/花费/上限/时间窗，再调用上一节query/mass_edit预算/product-edit ROI及pause/resume。每日重设按默认预算分组，批失败可单条降级。源23:30按站点时区，目标仅TW；恢复各类单项alarm的保证需单独查验。

停止监控只阻止后续加预算，不把已加额度减回。新增广告预算可能真实花钱；测试默认全接口本机stub，真实预算功能另列额度／次数／店铺授权。

## 6. 利润、账号、站点与管理（M05–M08）

### 利润与浮窗

`popup.js`计算器入口和`floatingEnabled`开关，`chrome.storage.sync`保存显示/位置；`content.js`在卖家页生成拖动浮窗，输入成本／汇率／费用并即时计算。后台另有`calculator`／`CALCULATOR_TOGGLE/CALCULATE/SETTINGS`。本地公式：净销售人民币=售价×(1−扣点)×(1−服务费)/汇率；利润再减采购、贴单、重量运费、宅配、国内运费、包邮及其他成本，利润率与保本ROI按相同币种计算。费率不是实时平台规则；新功能验收应验证各输入单位和零分母，不调用收费API。

### 本地模式和遗留SaaS链

`licenseAPI.isLocalMode/getLocalModeAuthInfo/getAuthInfo/loginUser/registerUser/bindShop`保留真实服务端分支；没有真实token时本地授权合成仅内存、全功能默认开放/额度门控可旁路。源实际API基地址当前本机3000，旧CLAUDE描述的远程地址过时。源登录注册表单和后台路由存在，不代表本地用户必受服务许可限制。目标保留自己的真实权限／试用／绑定，不移植这个回退。

### 站点、通知、导出与分发

`site-config.js`与manifest仍有TW/MY/TH/ID/VN/SG/PH/BR/MX；实际popup固定TW、启动写tw，background `saveSiteConfig`仅接受tw。多站配置不等于当前多站入口。source通知按登录/heartbeat/active接口进`pendingNotifications`，popup版本过滤、普通阅读确认、强制不可取消下载，管理员定向发布；目标已有不同修订／撤回／查看统计契约，不回退为源方案。

dashboard报表通过XLSX/下载生成Excel或CSV；topup规则本机快照是保存，不是配置文件导入；源没有确认的JSON配置导入入口。popup `createWindowSafely`优先windows.create、失败tabs.create。源打包obfuscator/archiver，目标继续WXT；anti-debug与死代码不迁移。
