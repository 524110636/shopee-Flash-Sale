规划方以独立测试数据通过真实本地 HTTP 复现下列响应；测试 JWT、Cookie 标记、店铺号均虚构，没有读取正式 DB/env 或真实店铺凭据。

**409 提示丢失根因已证实：** popup/backend-api.ts 的 request 保留后端 JSON error，但 store.ts 的 bindCurrentStore catch 在已登录情况下统一返回“绑定失败，请确认后端服务可用”。StoreStatus 把该返回值直接显示。规划方用 esbuild 将现有 store/backend-api 编译到自己的临时诊断 harness（仅注入本地地址、禁用 fallback、替换 browser.storage 为空测试实现），以真实隔离账号登录并调用实际 bindCurrentStore；409 与超限 403 均返回该通用错误。没有改业务源码，不只是按字符串猜测。根因是前端动作覆盖原因，不是这两个正常后端状态码错配。用户未提供当时具体请求，因此只能确认已复现同类错误，不能断定当时每个参数。

### 额外发现的两项既有异常

1. `stores.ts` 无 shopId 的兼容分支查询 spcCds 后，不检查 existing.userId，自己的已有绑定也返回 409 “其他用户绑定”；规划方以 owner 对自己同一虚构 SPC_CDS 再绑定、故意不传 shopId 复现。与有 shopId 时同用户更新的 200 行为不一致。

调查范围只读业务代码，并仅写自己的测试库；模拟 DB 错误使用自建库上的临时触发器，随后移除，没有碰正式数据库。上述问题在 stores/store 既有代码中，本次迁移未修改；建议未来修复时先恢复已知安全业务错误的展示、区分无 shopId 的同用户绑定、仅将 JSON 解析错误映射为 400。此处不是新的迁移返工任务，未擅自改授权、试用消耗或绑定规则。

### 管理入口行为

`App.tsx` 的 `openAdminSite()` 取 `backendApi.getBaseUrl()`：

- 地址为空 → 不打开页面，显示「未配置后端地址，无法打开管理网站」
- `window.open` 返回 null（被拦截）→ 提示里带完整地址供手动复制
- 正常 → 新标签页打开 `<基地址>/admin/`
- **无生产地址回落**：地址只来自用户配置或构建期默认值

**提示的渲染位置**：`adminSiteNotice` 提示块紧跟顶栏之后、`perspective` 翻转容器之前。**不能**把它放进下面的内容分支——那些分支受店铺绑定状态（「请先绑定店铺」／「当前店铺未绑定」）和复制模式控制，管理员在这些状态下点顶栏「管理」时提示将不可见。这是规划方 6.5 指出的缺陷，已修正并加了断言。

### 一处行为变化（请留意）

旧代码里三个门控条件都带 `&& !showAdminPanel`，作用是「管理员打开旧面板时不被店铺绑定提示挡住」。旧面板已删除，这三个 `!showAdminPanel` 随之移除，**管理员现在也会正常看到店铺绑定类提示**（「请先绑定店铺」／「当前店铺未绑定」／「正在同步店铺信息」）。

管理入口本身不受影响 —— 它是顶栏按钮，与门控分支无关。本轮已专门加一条浏览器断言守住这点：把隔离库里管理员的有效绑定全部置为无效后，页面显示「请先绑定店铺」，顶栏「管理」按钮仍可点击并正确打开 `/admin/`，断言通过后已复原隔离库。

## 2. 顺带修掉的一个真实缺陷（超出原计划，需你知晓）

排查中发现 **`backend/src/db/schema.ts` 的时间戳默认值是坏的**，且**在我改动之前就已存在**（已用 `git show HEAD:` 确认基线一致）。

**问题**：Drizzle 的 `.default('CURRENT_TIMESTAMP')` 会把字符串当**字面量**写进 SQL，于是该列永远存字符串 `"CURRENT_TIMESTAMP"`，而不是真实时间。

**实测影响面**（本地开发库）：

| 表.列 | 总行数 | 存成字面量 |
| --- | --- | --- |
| `users.created_at` / `updated_at` | 4 | 3 |
| `invite_codes.created_at` | 4 | 4 |
| `verification_codes.created_at` | 3 | 3 |
| `analytics_events.created_at` | 85 | 85 |
| `store_bindings.created_at` | 18 | 18 |

**为什么本轮必须修**：任务要求邀请码「显示使用时间」、统计展示事件时间——不修则显示的是 `CURRENT_TIMESTAMP` 这串字符，功能等于不成立。

**修法**：把 6 处 `.default('CURRENT_TIMESTAMP')` 改为 `.default(sql\`(datetime('now'))\`)`，让 SQLite 真正求值。

**修了之后**：
- 新写入的记录时间正确（已用隔离库验证，33 项检查含专项时间戳断言）。
- **历史数据里的字面量不会被自动修复**，前端把这类值显示为「时间待补全」（不显示也会显示成乱码，明示更诚实）。
- 是否需要回填历史数据，**由你决定**，本轮未做（属数据修改，超出授权）。
