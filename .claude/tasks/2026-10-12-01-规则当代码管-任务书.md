## 三、先定义清楚，避免各说各话

### 3.1 文档内容分三类，处理方法不同

| 类 | 是什么 | 处理 |
| --- | --- | --- |
| **A 规矩** | 告诉人或智能体"该怎么做 / 什么是真的"，且**今天仍然成立** | **留**，并在其后补一句"为什么需要它" |
| **B 旧规矩** | 描述的是本项目**现状 / 做法**，但代码里查不到、或值不符 | **删**，或改成与代码一致（拿不准时见 3.3） |
| **C 历史记录** | "（v1.7.0）改了什么""最近更新"这类**已完成工作的流水账** | 交任务 B 处理，**不补"为什么"**（补了是噪音） |

**判断 A / B / C 的硬标准：这一条能不能在代码里找到对应物？**
找不到、且描述的是"现状 / 做法" → **B**；找不到、但描述的是"当时干了什么" → **C**。

### 3.2 "为什么"那句话怎么写

- 加在该条**原文句末**，格式固定：` —— 为什么：<一句话，说清不遵守会出什么事、或用户会看到什么后果>`
- 例：原句「`consumeTrial()` 由 `runEnableLoop` 成功后 fire-and-forget 调用」→ 补成
  「……fire-and-forget 调用 —— 为什么：它不能阻塞开卖流程，否则慢网络下用户卡在等待界面；且它失败也不该让已经成功的开卖被回滚」
- **不许写**"因为这是规范""为了保持一致""这样更清晰"这类等于没说的话。
- **写不出具体后果 → 说明这条你也没理解。不要编**，把它记进"待规划方确认清单"（表 3），原文照留。

### 3.3 安全阀（最重要，先看这条再看别的）

1. **只做三种动作：删除 / 改值 / 补"为什么"。不做改写、不重写、不精简。** 原文能留就原样留。
2. 一条规矩如果描述的是**用户可见行为或防事故**（例如"后台必须用 `getSpcCdsFromCookies()` 读 SPC_CDS""X 为空时要保留原数据防崩溃"），**即便搜不到同名符号，也不许直接删** —— 必须先判断是"真的不存在"还是"改名 / 换位置了"。判断不了 → **不动**，记进表 3。
3. 删任何一条之前，台账里必须写清**你执行了什么检索、结果如何**。**没有检索证据的删除，一律视为未完成。**

### R7（必做，用户新要求）开发期后端指向本地

**但不能只改 `.env`** —— 这是本项的关键陷阱，两个坑，缺一不可：

1. **后端地址是"构建时"烤进产物的，不是运行时读的。** `import.meta.env.VITE_BACKEND_URL` 出现在 **5 处**：`entrypoints/background.ts:8`、`entrypoints/popup/backend-api.ts:12`、`entrypoints/popup/store.ts:346`、`:2695`、`:2707`。
   直接把 `.env` 改成 localhost，`npm run build`（**生产构建**）也会指向 localhost → **用户日常用的插件会连不上后端**。这是绝对不能出的错。
2. **兜底地址必须一起改。** `.env` 里 `VITE_BACKEND_FALLBACK_URL` 也是生产 IP（`entrypoints/background.ts:9`、`entrypoints/popup/backend-api.ts:10`）。若不改，本地后端一停，`tryFetch()` 会**静默回落到生产** —— 正好是用户要避免的事。

**做法：用按模式分离的 env 文件**（WXT / Vite 原生支持，**不需要改任何源码**）：

| 文件 | 内容 | 何时生效 |
| --- | --- | --- |
| `.env.development`（**新建**） | `VITE_BACKEND_URL=http://localhost:5724`<br>`VITE_BACKEND_FALLBACK_URL=`（**必须留空**，禁掉回落生产） | 只有 `npm run dev`（mode=development）加载 |
| `.env.production`（**新建**） | `VITE_BACKEND_URL=http://43.99.86.228:5724`<br>`VITE_BACKEND_FALLBACK_URL=http://43.99.86.228:5724` | 只有 `npm run build` / `npm run zip`（mode=production）加载 |
| `.env`（**保持不动**） | 现状 | 兜底；被上面两个覆盖 |
