## 附：R7 摘要（权威文本在任务书第十二节 R7）

用户在 2026-10-12 追加要求：**开发期间把前后端关联的服务器地址，从生产 `http://43.99.86.228:5724` 改指向本地 `http://localhost:5724`**。规划方已认可。

**为什么不能只改 `.env`（两个坑）**：

1. 后端地址是**构建时**烤进产物的（`import.meta.env.VITE_BACKEND_URL` 共 5 处：`background.ts:8`、`backend-api.ts:12`、`store.ts:346/2695/2707`）。直接把 `.env` 改成 localhost，`npm run build`（生产构建）也会指向 localhost → **用户日常用的插件会连不上后端**。
2. `.env` 里 `VITE_BACKEND_FALLBACK_URL` 也是生产 IP（`background.ts:9`、`backend-api.ts:10`）。不改的话，本地后端一停就**静默回落到生产** —— 正好是用户要避免的。

**做法（WXT/Vite 原生支持，不改任何源码）**：

| 文件 | 内容 | 生效时机 |
| --- | --- | --- |
| `.env.development`（新建） | `VITE_BACKEND_URL=http://localhost:5724`；`VITE_BACKEND_FALLBACK_URL=`（**留空**） | 只有 `npm run dev` |
| `.env.production`（新建） | 两个都填生产 IP | 只有 `npm run build` / `zip` |
| `.env`（不动） | 现状 | 兜底，被上两个覆盖 |

- 优先级：`.env` < `.env.local` < `.env.[mode]` < `.env.[mode].local`（Vite 官方）。
- `wxt` = mode `development`；`wxt build|zip` = mode `production`（已从本地 WXT 0.20.25 类型定义核实，仍需实测）。
- `.env.development` / `.env.production` **不在 `.gitignore`**（只忽略 `.env` 与 `*.local`）→ 新建后会进版本库，这是想要的。
- **验证**：`npm run build` 后 grep `.output/chrome-mv3/background.js` 应含 `43.99.86.228` 且**不含** `localhost:5724`；`npm run dev` 后对 `.output/chrome-mv3-dev/background.js` 应**相反**。两条 grep 命令与结果要写进台账。

**配套**：① 本地后端要跑起来 `cd backend && npm run dev`（实测 5724 当前无监听）；② 本地要有账号，`cd backend && npm run seed`（幂等）——本地库与生产库是两套数据，你原来的账号/绑定/试用状态都在生产库。

**两个已知坑**（写进 `运维速查.md`）：① `store.ts` 的 `setBackendUrl` 会把地址持久化到 storage 的 `backendUrl`，读取时**优先于** env 默认值；切换后若仍连旧地址要清 storage。② `AuthPanel.tsx:140` 管理员可见后端地址输入框，那是运行时手动覆盖，冲突时以 storage 为准。
